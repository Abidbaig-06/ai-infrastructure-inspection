2. Pipeline — image in, structured inspection out

2.1 Request path

Officer opens the AI Vision tab for a complaint → frontend calls POST /api/ai-agent/vision with { imageUrl, title, category } → aiAgentController.visionInspect → nvidiaVisionEngine.detectDefectsNvidia().

2.2 Image handling

  • http(s) URL (hosted photo) → passed straight to NIM as image_url.url; NVIDIA fetches it server-side.
  • base64 data: URI (citizen phone upload) → passed inline if ≤ 180 KB.
  • Neither / oversized → deterministic fallback (see §4).

2.3 The prompt — one vision-LLM call

System role: “infrastructure inspection vision model for a municipal corporation… respond with ONLY a compact JSON object.”

User message = the image + a strict JSON schema the model must fill, framed as an 8-stage municipal inspection. Returned in one shot:

FieldMeaning
infrastructureType + infrastructureConfidenceROAD / BRIDGE / BUILDING / DRAINAGE / WATER_PIPELINE / ELECTRICAL / STREET_LIGHT / OTHER

Call params: temperature 0.2, top_p 1, max_tokens 1024, stream false — low temperature keeps the JSON well-formed and the assessment grounded, not creative.

2.4 Response parsing & hardening

  • Extract the JSON object from the reply — tolerates stray text / code fences (slices first { to last }).
  • Every field clamped / normalized:
    • clampPct → all coordinates forced into 0–100
    • normalizeSeverity → free text → CRITICAL / HIGH / MEDIUM / LOW
    • normalizeInfraType → free text → one of 8 buckets
    • thermal percentages re-normalized to sum 100
    • missing values derived — zone center = defect centroid, hotspots = defect centers, deterioration = f(severity)
  • Output = the full 8-stage payload the frontend renders.

3. Reliability layer

MechanismBehavior
Key pool + rotationNVIDIA_API_KEYS (comma-separated) used round-robin; a request hitting 401 / 403 / 408 / 429 / 5xx rotates to the next key and retries.
Per-request timeoutAbortController at NVIDIA_TIMEOUT_MS (default 9000 ms) so a stalled key can't freeze the Vercel function (Hobby kills at 10 s). The 11B model was chosen over 90B to finish inside that window.
Deterministic fallbackNo key / no usable image / all keys fail / unparseable JSON → the engine still returns the identical full shape so the tab always renders. Fallback summary, keyFindings, recommendations, recommendedAction are derived from category + defect type + severity + moisture flag (not one fixed string); the failure reason is tagged in engine.

The engine field tells you which path ran:

  • nvidia:meta/llama-3.2-11b-vision-instruct → live model, per-image summary
  • fallback (<reason>) → deterministic, category-derived summary
  • nvidia-unparsed → model replied but not valid JSON

5. Configuration

NVIDIA_API_KEYS      = nvapi-...,nvapi-...      (pool, round-robin + failover)
NVIDIA_VISION_MODEL  = meta/llama-3.2-11b-vision-instruct
NVIDIA_TIMEOUT_MS    = 9000                     (< Vercel Hobby 10s function cap)
NVIDIA_BASE_URL      = https://integrate.api.nvidia.com/v1   (default)
